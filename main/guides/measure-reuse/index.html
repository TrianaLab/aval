    Measure reuse¶

    Goal: find out how often Aval would reuse a result, and whether reuse would have been right, before you let it skip any test.

    flowchart LR
  run([aval run --shadow]) --> v[verify] --> t[run the test anyway]
  t --> same{same result?}
  same -- yes --> ok([reuse would be correct]):::ok
  same -- no --> fh([FALSE HIT, exit 1]):::err
  t --> rec([run record in the registry]):::muted

    The example¶

    Run in shadow mode and record every run:

    aval run --shadow --record --registry ghcr.io/acme/orders-aval --policy policy.yaml

    --shadow verifies as usual, then runs the test anyway. If a verified result exists and agrees with the run, Aval prints shadow: reuse of <reference> would have been correct. If it disagrees, Aval prints aval: FALSE HIT: ... and exits 1. A false hit usually means the contract misses an input: fix the scope before you turn shadow mode off.

    --record publishes one run record per run. A record looks like this:

    {
  "version": "aval.trianalab.io/run-record/v1",
  "testId": "orders-integration",
  "fingerprint": "sha256:3f9a7c2e1b4d5f60718293a4b5c6d7e8f9012a3b4c5d6e7f8091a2b3c4d5e6f7",
  "outcome": "verified",
  "reused": true,
  "result": "passed",
  "verifiedResult": "passed",
  "testDurationMs": 0,
  "savedDurationMs": 1184000,
  "avalVersion": "0.3.0",
  "recordedAt": "2026-11-06T09:00:00Z",
  "ciRunUrl": "https://ci.example.com/acme/orders/runs/42",
  "repository": "acme/orders"
}

    Record from where you can write¶

    The job that runs the test has write access to the registry:

    aval run --record --registry ghcr.io/acme/orders-aval --policy policy.yaml

    The test job writes the record to a file. A job with write access, which runs no tests, publishes it:

    aval run --record-file record.json --registry ghcr.io/acme/orders-aval --policy policy.yaml
aval record --record-file record.json --registry ghcr.io/acme/orders-aval

    Aval's own CI does this on main for its end-to-end suite.

    Read the numbers¶

    aval stats reads the records back and sums them per test: hits, misses by cause, verification failures, shadow false hits and time saved.

    aval stats --registry ghcr.io/acme/orders-aval --since 7d

    run records in ghcr.io/acme/orders-aval since 2026-10-31T12:30:00Z
orders-e2e: 2 runs, 0 reused (hit rate 0.0%), test time 1m1s, saved 0s
  not reused: 1 no trusted result, 0 error, 1 verified but run (shadow)
  verification failures: 0, shadow false hits: 0
orders-unit: 1 runs, 1 reused (hit rate 100.0%), test time 0s, saved 1m30s
  not reused: 0 no trusted result, 0 error, 0 verified but run (shadow)
  verification failures: 0, shadow false hits: 0
total: 3 runs, 1 reused (hit rate 33.3%), test time 1m1s, saved 1m30s
  not reused: 1 no trusted result, 0 error, 1 verified but run (shadow)
  verification failures: 0, shadow false hits: 0

    --test limits it to one test, --by repository groups by source repository, and -o json prints the stats report. aval stats writes nothing and never affects reuse.

    Records are statistics, not evidence

    Records are unsigned. aval run and aval verify never read them, so a forged record cannot cause reuse. Recording is best-effort: a record that cannot be published prints aval: warning: run record not published and never changes the exit code.

    What the fields mean

    reused is true when the test did not run. savedDurationMs is how long the reused run took when it was recorded. With --shadow, reused is always false. Every field is in Artifact format: run records.
