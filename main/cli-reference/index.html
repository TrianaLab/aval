    CLI reference¶

    Every command, flag and exit code.

    Exit codes¶

    Code aval run aval verify aval push
    0 the test passed, or a verified passing result was reused a verified result exists (passing or failing) and no attestation failed verification pushed
    1 error (the test still runs when it can), or a false hit in --shadow error: registry, policy, trusted root or fingerprint error: signing, registry or a result that does not match the current inputs
    2 bad flags or invalid aval.yaml bad flags or invalid aval.yaml bad flags or invalid aval.yaml
    3 the test failed, or a verified failing result was reused not used not used
    4 not used: a miss runs the test miss: no result the policy can reuse not used
    5 verification failed, after running the test: a security event, also beside a verified result (never reused then) or over the 64-attestation cap; wins over 3 and 1 verification failed: a security event, also beside a verified result (the report keeps outcome verified) or over the 64-attestation cap not used
    6 reserved, never returned reserved, never returned reserved, never returned

    A miss (4) is routine. A verification failure (5) means someone published a result the policy does not trust; never hide it or retry it away.

    aval¶

    Verifiable test execution reuse: signed test results as OCI artifacts.

    --registry and --policy fall back to $AVAL_REGISTRY and $AVAL_POLICY; a flag wins, and an empty value counts as unset (an empty flag too: use --no-reuse to turn reuse off). run and verify then take the registry from the trust policy's registry field. There is no config file.

    Usage:
  aval [flags]
  aval [command]

Core:
  explain     Print what the execution fingerprint covers, with the digest last
  gen         Generate one test per unit from a dependency graph into a TestSet
  init        Write aval.yaml, a signing key and a trust policy for a test
  run         Reuse a verified result for the current inputs, or run the test
  verify      Check whether a trusted result exists for the current inputs

Publishing:
  keygen      Create a signing key: name.key and name.pub (default name: aval)
  push        Sign and publish a recorded execution result

Statistics:
  stats       Aggregate the run records in the registry: reuse, misses, time saved

Additional Commands:
  completion  Generate the autocompletion script for the specified shell
  help        Help about any command
  upgrade     Replace this binary with a verified aval release
  version     Print the aval version, Go version and platform

Flags:
  -h, --help[=true|false]      help for aval
      --plain[=true|false]     plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)
  -v, --version[=true|false]   version for aval

Use "aval [command] --help" for more information about a command.

    aval explain¶

    explain prints the fingerprint manifest (every input that was hashed) under a header, then the fingerprint as the last line. --digest prints only the fingerprint. explain never looks up a result and never runs the test; the fingerprint is the one 'aval run' computes with its default --result-file and without --report-file or --stats-file inside the contract root. With scope.root it prints the resolved root after the header. Each scope.optionalSource glob that matched no file is named on stderr.

    --expand prints the test as the standalone kind: Test it expands to (a test of a TestSet with defaults, fragments and matrix applied). --all checks every test of the file: it prints one "name fingerprint" line per test (-o json: one object per test), reports every failing test by name instead of stopping at the first, and executes nothing, not even environment.probe.

    Exit codes: 0 printed, 1 the fingerprint cannot be computed (unprovable inputs), 2 usage or invalid aval.yaml. With --all, 2 when any failing test is invalid, else 1 when any fingerprint cannot be computed.

    Usage:
  aval explain [flags]

Examples:
  # What the fingerprint covers, digest last
  aval explain

  # Only the digest
  aval explain --digest

Flags:
      --all[=true|false]      check and fingerprint every test of the file, one line per test
  -f, --contract string       path to the test contract (default "aval.yaml")
      --digest[=true|false]   print only the fingerprint (sha256:...)
      --expand[=true|false]   print the test as the standalone kind: Test it expands to
  -h, --help[=true|false]     help for explain
  -o, --output string         output format of --all: text or json (default "text")
  -t, --test string           the test to use, by metadata.name: required on a TestSet of more than one test; output files default to .aval/<test>/

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    aval gen¶

    gen writes declared scope from a repository's dependency graph into the kind: TestSet in -f. For each unit (a package, module or project) it writes a fragment with the unit's own files and a test that uses the fragments of the unit and of every unit it depends on, both named LANGUAGE.UNIT (such as go.internal.contract). A change to a unit then re-runs its test and the tests of the units that depend on it.

    gen owns only the fragments and tests whose names start with "LANGUAGE."; every other line, comments included, is kept as it is. Shared inputs (lockfiles, root build files, toolchain, cacheability) belong in the hand-written defaults. --no-test PATTERN (repeatable, a contract glob such as cmd/gen* or tests/**) writes no test for the units whose ID matches; they keep their fragment, so their files stay in the scope of the tests that use them. aval run, verify and push never run gen: commit its output and check it in CI with --check.

    Languages: dotnet, go, java, js, python, rust.

    Exit codes: 0 written or up to date, 1 error (the language tool failed, the dependency graph is invalid, the file cannot be written) or with --check out of date (the diff is printed), 2 usage (an unknown language, no TestSet at -f, a --no-test pattern that matches no unit, or a result that is not a valid TestSet).

    Usage:
  aval gen <language> [flags]

Examples:
  # Write one test per unit into aval.yaml
  aval gen <language>

  # In CI: fail with a diff when aval.yaml is out of date
  aval gen <language> --check

Flags:
      --check[=true|false]            write nothing; exit 1 with a diff when the generated entries are out of date
  -f, --file string                   the kind: TestSet to write (default "aval.yaml")
      --go-cover[=true|false]         go: each test fails below 100% statement coverage of its package (needs sh, mktemp and awk)
  -h, --help[=true|false]             help for gen
      --no-test stringArray           write no test for the units whose ID matches this contract glob; their fragment stays for the tests that use it (repeatable)
      --strict-imports[=true|false]   python: fail on an import_module or __import__ call whose module is not a string literal

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    aval init¶

    init writes aval.yaml for one test, validated before it is written. With --key NAME it also writes the signing key pair (NAME.key and NAME.pub, as keygen does; a trailing .key is dropped) and policy.yaml trusting that key at trust level developer. It adds the key and .aval/ to .gitignore. --keyless writes no key and no policy.

    Nothing is inferred: --source and --cacheability have no default, and init never traces the test. It lists the files the source globs match and rejects a glob that matches nothing. It never replaces aval.yaml, policy.yaml or the key without --force. If a write fails after the key pair was written, init removes the key pair again.

    --set writes a two-file starting layout instead: aval.yaml as a kind: TestSet with the test and one fragment that holds the source globs, and .github/aval/policy.yaml with one placeholder keyless identity (an anchored subjectRegexp with a placeholder owner and repository that matches nothing until you edit it). It writes no key. Both files are validated before they are written; on an existing file it exits 2 unless --force.

    When a value is missing and both stdin and stdout are terminals, init asks for it. Otherwise it exits 2 and names the missing flags.

    Exit codes: 0 written, 1 error (a file exists without --force, or cannot be written), 2 usage (a missing value, an invalid contract, a glob that matches nothing, init cancelled, or with --set a file exists without --force).

    Usage:
  aval init --name NAME --source GLOB... --cacheability CLASS --key NAME|--keyless|--set [--force] -- <command> [flags]

Examples:
  # Write aval.yaml, aval.key, aval.pub and policy.yaml
  aval init --name unit --source 'src/**' --source go.mod --cacheability hermetic --key aval.key -- go test ./...

  # Start a TestSet: aval.yaml and .github/aval/policy.yaml with a placeholder identity
  aval init --set --name unit --source 'src/**' --cacheability hermetic -- go test ./...

Flags:
      --cacheability string    hermetic, controlled-environment, external-dependencies or non-deterministic
      --force[=true|false]     replace existing aval.yaml, policy.yaml and key files (.github/aval/policy.yaml with --set)
  -h, --help[=true|false]      help for init
      --key string             signing key pair NAME.key and NAME.pub to create and trust in policy.yaml; a trailing .key is dropped
      --keyless[=true|false]   sign keyless with Sigstore: no key and no policy are written
      --name string            test name (metadata.name): what the test checks
      --set[=true|false]       write aval.yaml as a kind: TestSet and .github/aval/policy.yaml with a placeholder identity, no key
      --source stringArray     source glob relative to the current directory (scope.source); repeat it for more

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    aval keygen¶

    keygen writes a new ECDSA P-256 signing key to name.key (unencrypted PKCS#8 PEM, mode 0600) and its public key to name.pub, the file a policy trusts with publicKey. It prints the key id the verify report shows for this signer. It refuses to replace either file without --force. A trailing .key in the name is dropped, so "aval keygen ci.key" writes ci.key and ci.pub.

    Exit codes: 0 written, 1 error (name.key or name.pub exists without --force, or cannot be written), 2 usage.

    Usage:
  aval keygen [name] [flags]

Examples:
  aval keygen        # aval.key and aval.pub
  aval keygen ci     # ci.key and ci.pub

Flags:
      --force[=true|false]   replace name.key and name.pub if they exist
  -h, --help[=true|false]    help for keygen

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    aval push¶

    push signs the result recorded by 'aval run' and publishes it. The result must be for the current inputs: same test id, cacheability and fingerprint. --report-file names the report that run wrote with the result: when its outcome is verified (also under --shadow), push publishes nothing and exits 0; when it records a security event (outcome verification-failed, or a rejected attestation that failed verification), push publishes nothing and exits 5. A non-deterministic test is never pushed: push publishes nothing and exits 0. With --test, the result and the report must both be for that test. --outputs-dir reads the contract's outputs from the directory that 'aval run --outputs-dir' filled, not from the contract root: any entry in it that is not a regular file matched by an outputs glob publishes nothing. The directory may be missing only when the contract declares no outputs. --env-file takes the env section of the fingerprint from the file that 'aval run' wrote with the result (hashes of environment.env, no values), not from this process's environment, so a job with other variables can publish it. Every other input is still hashed from the checkout. A file with another manifest version, a malformed or repeated line, or names other than environment.env publishes nothing. Keyless signing reads the OIDC token from $SIGSTORE_ID_TOKEN. Without --key or $SIGSTORE_ID_TOKEN, signing on a terminal (or with --login) opens the interactive Sigstore login in the browser; no token is stored.

    Usage:
  aval push [flags]

Examples:
  aval push --registry ghcr.io/acme/orders-aval --key aval.key

Flags:
  -f, --contract string             path to the test contract (default "aval.yaml")
      --env-file string             take the env section of the fingerprint from this file ('aval run --env-file') instead of this process's environment
  -h, --help[=true|false]           help for push
      --key string                  signing key path (default: keyless OIDC)
      --login[=true|false]          sign keyless after the interactive Sigstore login, even without a terminal (overrides: $SIGSTORE_OIDC_ISSUER, $SIGSTORE_OIDC_CLIENT_ID)
      --outputs-dir string          read the contract's outputs from this directory ('aval run --outputs-dir') instead of the contract root; anything in it that is not a declared output publishes nothing
      --registry string             OCI repository for attestations and run records, e.g. ghcr.io/acme/orders-aval (default: $AVAL_REGISTRY)
      --registry-timeout duration   deadline for this command's registry calls (default 1m0s)
      --report-file string          report written by the same 'aval run'; push nothing when it reused a verified result, and exit 5 when it records a security event
      --result-file string          result recorded by 'aval run' (default ".aval/result.json")
  -t, --test string                 the test to use, by metadata.name: required on a TestSet of more than one test; output files default to .aval/<test>/

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    Deprecated flags, hidden from help:

    • --result: use --result-file

    aval run¶

    run reuses a verified result for the current inputs when the trust policy accepts it, restoring the contract's outputs; otherwise it runs runner.command and records the result. Anything Aval cannot prove runs the test.

    Without a registry and a trust policy the test always runs. --registry-timeout covers lookup and fetch together; --push has its own. runner.command never sees $SIGSTORE_ID_TOKEN, $AVAL_REGISTRY, $AVAL_POLICY, $AVAL_MIN_TRUST_LEVEL or $AVAL_DOCKER_CONFIG, a directory whose config.json Aval reads registry credentials from instead of $DOCKER_CONFIG's (the test keeps $DOCKER_CONFIG).

    runner.command and the probes get $AVAL_RUN_STACK, the contracts of the enclosing aval runs. A run whose contract is already there exits 2 before doing anything: runner.command must not start the same contract again. A nested run of another contract works.

    Exit codes: 0 pass, 3 fail, 5 verification failed (a security event, after running the test: also a verified result beside a rejected verification-failed attestation, which is never reused, or more attestations than the lookup cap), 1 error or false hit (--shadow), 2 usage. 5 wins over 3 and 1.

    Usage:
  aval run [flags]

Examples:
  # Reuse a trusted result, or run the test
  aval run --registry ghcr.io/acme/orders-aval --policy policy.yaml

  # Run, then sign and publish the result keyless
  aval run --registry ghcr.io/acme/orders-aval --push

Flags:
      --ci-run-url string               link to the CI run, stored in the run record
  -f, --contract string                 path to the test contract (default "aval.yaml")
      --env-file string                 where to record the env section of the fingerprint (hashes, no values) with the result, for 'aval push --env-file' in another job (default ".aval/env.txt")
      --explain[=true|false]            print the fingerprint manifest (what was hashed) before the run; 'aval explain' prints it alone
      --fingerprint-only[=true|false]   print the execution fingerprint and exit (same as 'aval explain --digest')
  -h, --help[=true|false]               help for run
      --key string                      signing key path for --push (default: keyless, from $SIGSTORE_ID_TOKEN or the interactive login; no token is stored and runner.command never sees it)
      --login[=true|false]              sign keyless after the interactive Sigstore login, even without a terminal (overrides: $SIGSTORE_OIDC_ISSUER, $SIGSTORE_OIDC_CLIENT_ID)
      --min-trust-level string          raise the trust policy's minTrustLevel to developer, runner or isolated; a value below it exits 2 (default: $AVAL_MIN_TRUST_LEVEL)
      --no-reuse[=true|false]           always run, never reuse (excludes --shadow)
      --outputs-dir string              also copy the contract's outputs to this empty directory when the result is recorded, for 'aval push --outputs-dir' in another job (keep it outside the scope, e.g. under .aval/)
      --policy string                   trust policy file; without it nothing is reused (default: $AVAL_POLICY; an empty flag also falls back to it)
      --push[=true|false]               sign and publish the result after running (needs --registry)
      --registry string                 OCI repository for attestations and run records, e.g. ghcr.io/acme/orders-aval (default: $AVAL_REGISTRY, then registry in the trust policy)
      --registry-timeout duration       deadline for this command's registry calls (default 1m0s)
      --report-file string              also write the lookup decision as a verify report (JSON) to this file
      --result-file string              where to record the result for 'aval push' (default ".aval/result.json")
      --shadow[=true|false]             verify, but run the test anyway and exit 1 on a false hit (excludes --no-reuse)
      --source-repo string              source repository (e.g. acme/orders), stored in the run record for 'aval stats --by repository'
      --stats[=true|false]              publish a run record for statistics after the run (needs --registry; best-effort)
      --stats-file string               also write the run record to this file, for 'aval stats publish'
  -t, --test string                     the test to use, by metadata.name: required on a TestSet of more than one test; output files default to .aval/<test>/

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    Deprecated flags, hidden from help:

    • --record: use --stats
    • --record-file: use --stats-file
    • --report: use --report-file
    • --repository: use --source-repo
    • --result: use --result-file

    aval stats¶

    stats reads the run records that 'aval run --stats' and 'aval stats publish' published to the registry and aggregates them: runs, hit rate, misses by cause, verification failures, shadow false hits, and total and saved test time, per test (or per source repository with --by repository) and in total. It reads every test with a stats anchor, or only --test. It writes nothing, locally or to the registry.

    Run records are unsigned statistics and never affect reuse. Unreadable or invalid records are skipped and counted. Reading stops after 1000 records or 64 pages per listing; prune old records. Raise --registry-timeout for many records.

    --since keeps records made at or after a time: a duration back from now (168h, 30d) or a date (2026-11-01, or RFC 3339).

    Exit codes: 0 statistics printed, 1 error (registry), 2 usage.

    Usage:
  aval stats [flags]
  aval stats [command]

Examples:
  aval stats --registry ghcr.io/acme/orders-aval --since 30d

Available Commands:
  publish     Publish a run record written by 'aval run --stats-file'

Flags:
      --by string                   group by test or repository (the run record's source repository) (default "test")
  -h, --help[=true|false]           help for stats
  -o, --output string               output format: text or json (default "text")
      --registry string             OCI repository for attestations and run records, e.g. ghcr.io/acme/orders-aval (default: $AVAL_REGISTRY)
      --registry-timeout duration   deadline for this command's registry calls (default 1m0s)
      --since string                only records made since: a duration (168h, 30d) or a date (2026-11-01, RFC 3339)
      --test string                 only this test id (metadata.name); default: every test with run records

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

Use "aval stats [command] --help" for more information about a command.

    aval stats publish¶

    stats publish publishes the run record that 'aval run --stats-file' wrote to FILE, as 'aval run --stats' would have. Use it to publish, from a job with write credentials that runs no tests, the record of a run made without them. Run records are unsigned statistics: run and verify never read them. --source-repo sets the record's source repository.

    Usage:
  aval stats publish FILE [flags]

Examples:
  aval stats publish --registry ghcr.io/acme/orders-aval record.json

Flags:
  -h, --help[=true|false]           help for publish
      --registry string             OCI repository for attestations and run records, e.g. ghcr.io/acme/orders-aval (default: $AVAL_REGISTRY)
      --registry-timeout duration   deadline for this command's registry calls (default 1m0s)
      --source-repo string          source repository (e.g. acme/orders); default: the one in the record

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    aval upgrade¶

    upgrade downloads a release from GitHub Releases (the latest, or --version), checks that checksums.txt carries a keyless Sigstore signature from Aval's release workflow at that tag and that the archive matches it, then replaces the running binary. Any failed check replaces nothing. A bad signature or checksum is a security event: do not retry it away. Without --version it refuses to move to an older release than the running one.

    Exit codes: 0 upgraded or up to date (or --check printed), 1 error (download, signature, checksum, older latest release, replacing the binary), 2 usage.

    Usage:
  aval upgrade [flags]

Examples:
  aval upgrade --check

Flags:
      --check[=true|false]   print the current and target versions without installing
  -h, --help[=true|false]    help for upgrade
      --version string       release to install, e.g. v0.4.0 (default: latest)

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)

    aval verify¶

    verify computes the fingerprint, looks up the attestation and verifies its signature and the trust policy, without running anything. It needs a registry; without a trust policy every lookup is a miss.

    Exit codes: 0 verified, 4 miss, 5 verification failed (security event: also a verified result beside a rejected verification-failed attestation, or more attestations than the lookup cap), 1 error (registry, policy or fingerprint), 2 usage or invalid aval.yaml.

    Usage:
  aval verify [flags]

Examples:
  aval verify --registry ghcr.io/acme/orders-aval --policy policy.yaml -o json

Flags:
  -f, --contract string             path to the test contract (default "aval.yaml")
  -h, --help[=true|false]           help for verify
      --min-trust-level string      raise the trust policy's minTrustLevel to developer, runner or isolated; a value below it exits 2 (default: $AVAL_MIN_TRUST_LEVEL)
  -o, --output string               output format: text or json (default "text")
      --policy string               trust policy file; without it nothing is reused (default: $AVAL_POLICY; an empty flag also falls back to it)
      --registry string             OCI repository for attestations and run records, e.g. ghcr.io/acme/orders-aval (default: $AVAL_REGISTRY, then registry in the trust policy)
      --registry-timeout duration   deadline for this command's registry calls (default 1m0s)
  -t, --test string                 the test to use, by metadata.name: required on a TestSet of more than one test; output files default to .aval/<test>/

Global Flags:
      --plain[=true|false]   plain aval run output even on a terminal, as in CI (also $AVAL_OUTPUT=plain or TERM=dumb)
