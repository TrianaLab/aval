    Changelog¶

    0.11.0¶

    Minor Changes¶

    • c5b0404: aval gen <language> --no-test <pattern>: write no test for the units whose ID matches a contract glob (repeatable), for every language. Their fragment stays while another test uses it, so their files stay in that test's scope; a pattern that matches no unit is a usage error (exit 2), and --check compares the output of the same flags (docs: Guides, Generate scope from the dependency graph).

    0.10.0¶

    Minor Changes¶

    • 631f20b: aval gen <language>: the language-agnostic core that writes one fragment and one test per unit from a dependency graph into a kind: TestSet, with the transitive closure computed by Aval, stable <language>.<unit> names, hand-written entries kept byte for byte, and --check for CI. No language adapter ships yet (docs: Guides, Generate scope from the dependency graph).
    • 3ef1c25: aval gen dotnet: the .NET adapter of aval gen. One unit per project (.csproj, .fsproj, .vbproj) from the solution at the contract root, or every project file without one, read from the solution and project files without the .NET SDK. ProjectReferences become dependencies; imported files, Directory.Build.* and Directory.Packages.props files above a project and items included from outside its directory join its scope; the test is dotnet test <project> (docs: Guides, Generate scope from the dependency graph).
    • 128a40f: aval gen go: the Go adapter for aval gen. One unit per package of the main modules under the contract root, read with go list -deps -test -json: the package's .go files, go:embed files, non-Go sources and testdata, and its imports of other local packages from every .go file whatever its build tags. --go-cover makes each test fail below 100% statement coverage of its package (docs: Guides, Generate scope from the dependency graph).
    • e2127bc: aval gen java: the Java and Kotlin adapter. One unit per Maven module or Gradle subproject, read from pom.xml, settings.gradle(.kts) and build.gradle(.kts) without running a JVM tool; only references to modules of the same build become edges, and anything it cannot read for certain (computed paths, includeBuild, files outside the module directory) is an error (docs: Guides, Generate scope from the dependency graph).
    • 66b5c50: aval gen js: the JavaScript and TypeScript adapter. One unit per npm, pnpm or yarn workspace package, an edge for every dependency on another workspace package (by name, workspace:, file:, link: or portal:), and the test command of the package manager the lockfile names (docs: Guides, Generate scope from the dependency graph).
    • f7e1b80: aval gen python: one test per local Python project (uv workspace members, poetry and pip projects) with edges from declared dependencies and local imports, read by Python's own tomllib and ast. --strict-imports fails on a dynamic import it cannot resolve (docs: Guides, Generate scope from the dependency graph).
    • 1fef1dd: aval gen rust: one unit per Cargo workspace member, read with cargo metadata --no-deps, with path dependencies between members as edges and cargo test -p <member> as the test. A [patch] or .cargo/config.toml paths override outside every member fails closed (docs: Guides, Generate scope from the dependency graph).
    • da5d695: Publish action: new stats-registry input (host[:port]/path, validated; empty keeps the policy's registry). With stats: true it now publishes the run record of every artifact, verified hits and verification failures included, not only those whose result was pushed, so a consumer's runs reach a shared stats registry such as ghcr.io/trianalab/aval-stats. A failed record publish is still a warning; exit 5 handling is unchanged.

    Patch Changes¶

    • 05d392d: Dependencies: github.com/spf13/pflag 1.1.0. Its help output now shows boolean flags as --flag[=true|false]; the CLI reference is regenerated.
    • 3997c4c: aval gen: file and directory names with glob metacharacters (*, ?, [) are escaped in the generated scope, so a unit in such a directory keeps its own files in scope instead of silently matching nothing. A name no contract glob can express (a backslash) fails closed (exit 1, nothing written).
    • 68483ba: aval gen js: TypeScript project references and extends, and relative imports that cross into another workspace package, are now edges, so a test is no longer reused when a package it reaches only that way changes. A root tsconfig.base.json a package extends joins its files. A relative import outside every workspace package, or one that cannot be resolved, fails closed with the file and line (docs: Guides, Generate scope from the dependency graph).
    • 4c2dab4: aval gen: a kind: TestSet with old Mac (\r) line endings, or a stray \r, U+0085, U+2028 or U+2029 line break, no longer makes the rewrite panic: lines are counted the way the YAML parser counts them. Generated lines follow the file's line endings, so a \r\n file round-trips byte for byte.
    • 142b0a2: aval gen rust: a contract root reached through a symlink (a clone under macOS /tmp, a symlinked working directory) is no longer rejected with "outside the contract root". The root is made absolute before its symlinks are resolved, so it matches the canonical paths cargo prints; a member that really is outside the root still fails.

    0.9.0¶

    Minor Changes¶

    • 52911eb: environment.env accepts prefix patterns such as APP_* (#253): every set variable whose name starts with the prefix is hashed, one env NAME <sha256> line each, so a tool configured by prefix no longer needs every name listed by hand. * may only end the entry; *, *_TOKEN and patterns that would match AVAL_RUN_STACK (AVAL_*) are rejected. Names compare case-sensitively on Linux and macOS and case-insensitively on Windows. A pattern also hashes credentials that share the prefix; list exact names when it covers secrets. aval run records the matched variables in its env file, and aval push --env-file accepts the names a pattern matches. Contracts without a pattern keep their fingerprint; older aval binaries reject a contract that uses one.
    • 0c4a8b7: environment.paths declares files and directories outside the tree as fingerprint inputs (#254), such as ~/.config/pacto or ${XDG_CONFIG_HOME}/pacto. Each entry adds a path <entry> <hash> manifest line with the entry as written, so another $HOME with the same content shares a result; absent and unset are hashed too. A symlink, a special or unreadable file fails the fingerprint, and an entry inside the contract tree is a contract error. aval explain lists the lines. Format change: an additive optional contract field under the same apiVersion, with a manifest line kind only it brings; the manifest stays aval-fingerprint/v2 and existing contracts hash as before. An older aval rejects a contract that uses paths (unknown field), which fails closed.
    • cef4b7b: A TestSet matrix variable can be {count: N} (N from 1 to 1024): it takes the values "1" to "N" and defines {v_count} = N, so a sharded runner writes PW_SHARD={shard}/{shard_count} and the total is stated once. The expanded tests and their fingerprints are the same as the list form. A bad count, an extra key in the mapping, or a v_count variable beside a count variable v is a contract error (exit 2). Additive within aval.trianalab.io/v1: older aval binaries reject the mapping form.
    • 6c24fde: A TestSet matrix now substitutes {var} into environment.toolchain values, so one test can declare a value per leg (for example platform: "{os}") and each leg gets its own fingerprint. An unknown {var} in a toolchain value, or a {var} in a toolchain value of a test without a matrix, is now a contract error (exit 2); before, it was hashed as literal text. Contracts without {var} in toolchain values keep their fingerprints.
    • 7fa8978: scope.optionalSource declares source globs that may match no file yet (#257), for inputs a test discovers by pattern such as **/*testdata*.yaml. Matching files are hashed as source lines, with the same exclude rules, so adding the first one is a miss. A glob may not be in both source and optionalSource, and source plus optionalSource must still hash at least one file. aval explain names optional globs that matched nothing on stderr. Format change: an additive optional contract field under the same apiVersion; the manifest stays aval-fingerprint/v2. Existing contracts hash as before; an older aval rejects a contract that uses optionalSource (unknown field), which fails closed.
    • 597b9d6: The GitHub run action takes lookup-only: "true" (#252): it runs aval verify with the default branch's trust policy and trust minimum, sets the outcome output and never runs the test, uploads or writes .aval/. A later setup step can be skipped on verified; the run step after it still decides reuse. A miss succeeds the step, exit 5 fails it with the aval SECURITY annotation, and lookup-only with shadow: true exits 2.
    • da68465: The GitHub run action raises the trust minimum to runner on the default branch (#251), so main no longer goes green on a developer-signed result that aval push would then not publish. The new min-trust-level input (auto by default, or developer, runner, isolated) passes the highest of itself, the job's AVAL_MIN_TRUST_LEVEL and the policy's minTrustLevel, so it never lowers the policy's minimum; min-trust-level: developer opts out. A policy minimum of isolated is kept instead of failing with exit 2, and the log and step summary show the effective minimum. Workflows can drop their hand-written AVAL_MIN_TRUST_LEVEL expression.
    • c17e62f: The GitHub run action reads a private attestations registry: new optional inputs registry-username and registry-password (default empty, anonymous as before) write credentials for the host of the default-branch policy's registry only, in a directory of the step that is deleted when it ends. aval reads it through the new AVAL_DOCKER_CONFIG, a directory whose config.json replaces $DOCKER_CONFIG's for Aval's registry client and that runner.command never gets; the test keeps the job's DOCKER_CONFIG. The test no longer sees the job's GH_TOKEN.

    Patch Changes¶

    • d87eec2: The GitHub actions no longer put cosign on the job's PATH. They install the cosign that verifies the aval release into $RUNNER_TEMP, checked against a per-platform sha256, instead of using sigstore/cosign-installer, which writes GITHUB_PATH. The test and later steps see the job's own tools again.
    • 1261177: examples/github-monorepo and the "Integrate Aval in 5 files" guide that embeds it pin the GitHub actions at the commit that pins v0.8.2, with a # v0.8.2 comment, instead of a commit that installed v0.7.0 (#261). After each pin PR merges, the new pin-examples job of release.yaml opens a PR (branch release-pins/examples) that moves the examples to the merge commit, and pin-examples-ci dispatches ci on it. An architecture test fails when an example's action pin installs an older release than main pins (one pin behind is allowed while that PR is open) or when its comment names another version, and when a doc other than docs/install.md names a hard-coded aval version. docs/install.md now pins v0.8.2 in its example and says the verified-install flags first ship in v0.8.1. No CLI or format change.
    • 8f1912d: The pinning scanner no longer reports npx --no, npx --no-install, npm exec --no, pnpm exec and yarn exec: they run only what is already installed. Plain npx, npm exec, pnpm dlx, yarn dlx and bunx are still reported, as are packages named by -p, and the fix text now mentions npx --no <bin>.
    • 01177a9: The GitHub publish action downloads the aval-* artifacts right after its guard (#260). With none, it prints a notice and exits 0 without installing cosign or aval, fetching the policy or requesting an OIDC token, so a publish job that runs on !cancelled() after path-filtered test jobs no longer fails in a repository whose policy is not merged yet. With artifacts and no policy it still exits 1.
    • 311b2fc: aval push accepts a result from a job with other environment variables (#247). aval run writes an env file next to the result (--env-file, default .aval/env.txt, .aval/<test>/env.txt with --test): the fingerprint manifest version, then the manifest's env NAME unset|<sha256> lines, hashes only, neither signed nor published. aval push --env-file FILE takes the env section from it instead of its own environment; every source, dependency, toolchain and contract line is still hashed from the checkout, and the digest must still match the result and the report. A file with another manifest version, a malformed or repeated line, or names other than environment.env exits 1 and publishes nothing; inside the contract scope and outside .aval/ it exits 2, as --result-file does. Without the flag push is unchanged. The publish action passes the artifact's env.txt when the installed aval has the flag, so a variable such as GOTOOLCHAIN=local from setup-go no longer fails the push. No format change: the manifest stays aval-fingerprint/v2. docs/artifact-format.md documents the env file.
    • 5312533: The run action uploads aval-<test> with overwrite: true. Re-running a failed job no longer fails with 409 on the earlier attempt's artifact, and the publish job signs the result of the attempt that just ran. Run each test in only one job per workflow run.
    • 1634652: A symlink to a regular file under a ** source glob now needs only its name in exclude (#258); <link>/** is no longer required, since no path exists under a file. A link to a directory, a dangling link or a loop still needs both. The link is never followed nor hashed; Aval only checks its target's type. The error names the exclude that would fix it. Dropping <link>/** from a contract changes its hash, so the next run is a miss.

    0.8.2¶

    Patch Changes¶

    • 422352d: The GitHub actions carry a test's outputs from run to publish (#236). aval run --outputs-dir DIR copies the files the outputs globs matched into an empty DIR when it records the result, and aval push --outputs-dir DIR publishes them from there instead of the contract root, refusing (exit 1, nothing published) any entry that is not a regular file matched by an outputs glob: a symlink, an extra file, an input, .git or .aval. The run action passes --outputs-dir .aval/<test>/outputs on a push to the default branch; the publish action passes the artifact's outputs/, so a test with outputs and no outputs/ exits 1 instead of publishing the checkout's files, and it refuses an artifact with any entry outside result.json, report.json, record.json and outputs/. docs/guides/github-actions.md documents the artifact layout. No format change. This closes the known gap noted in 0.8.1 (the publish action could not push a test with outputs). With a pinned release without --outputs-dir (0.8.1), the actions keep running and publishing tests without outputs, and refuse a test with outputs, as aval explain --expand reports it, with exit 1 naming aval v0.8.2 or later, instead of dropping its outputs or signing the checkout's files.
    • 8f78554: The aval run action takes a shadow input (default false): true passes aval run --shadow, so the test runs beside a verified result and a false hit fails the step; any value other than true or false exits 2 before anything runs (#216). The job's AVAL_MIN_TRUST_LEVEL still reaches aval, which only lets it raise the policy's minimum. Aval's own CI now runs its suites through integrations/github/run and publishes through integrations/github/publish: aval.yaml is a kind: TestSet with the tests aval-engine and aval-e2e (same fingerprints as the former aval.yaml and aval.e2e.yaml), one .github/aval/policy.yaml carries the registry and replaces main.yaml and pr.yaml (main and releases raise the minimum to runner), and .github/aval/install.sh, trust-from-base.sh and summary.sh are removed. The release gate verifies with the release the actions pin, under main's policy. No change to the aval binary, its exit codes or formats.
    • 15cc546: Build with Go 1.27.4, which fixes GO-2026-6859 in net/http (govulncheck reports it as reachable from required modules, not from Aval's code).

    0.8.1¶

    Patch Changes¶

    • 806588c: New guide "Integrate Aval in 5 files" and the example examples/github-monorepo (#217): a monorepo with a Go module, a Node UI, a Dockerfile, a data directory and an end-to-end suite in 3 shards, put on Aval by adding aval.yaml and .github/aval/policy.yaml and editing ci.yml and .gitignore. Aval's tests check that the integration is exactly those files, run every test through the CLI (miss and push, reuse per shard, a fragment edit reruns only its tests, an unaccepted mutable reference, exit 5 on a tampered attestation), and CI checks that the run action ignores a trust policy edited in a pull request. No CLI or format change. Known gap: the GitHub publish action cannot push a test with outputs yet, because the run action's artifact holds .aval/<test>/ only.

A newer aval computes aval-fingerprint/v2, so the gate missed (exit 4) on v0.8.0 and published nothing: the v0.8.0 tag has no GitHub Release, and this patch ships its changes as v0.8.1.

    0.8.0¶

    Minor Changes¶

    • 7de8cd6: scope.allowMutable entries take an optional files list of globs (#208). One entry accepts its exact ref in every file in scope a glob matches, instead of one entry per file. files excludes file, which stays an exact path; each glob must match a file in scope, otherwise aval exits 2. Format change: an additive optional contract field under the same apiVersion. Existing contracts hash as before; an older aval rejects a contract that uses files (unknown field), which fails closed.
    • b0b968a: Every security event Aval detects now exits 5 (#195). A verified result beside an attestation that failed verification is no longer reused: aval run runs the test and exits 5, and aval verify exits 5 with the unchanged report (outcome verified, the bad attestation in rejected). More than 64 attestations for one fingerprint is now outcome verification-failed (exit 5 in aval run and aval verify) instead of error. The run record of such a run says verification-failed, so aval stats counts it under verificationFailures. Consumers no longer need to inspect rejected: the exit code alone separates miss, error and security event. No new outcome or exit code; the verify report, predicate and fingerprint are unchanged.
    • b518636: New GitHub composite action integrations/github/publish (#212): one step in the consumer's own publish job signs and pushes every aval-<test> artifact the run action uploaded in the workflow run. It refuses any ref but the default branch unless allow-unprotected: true, always refuses pull_request_target and workflow_run, and needs id-token: write; installs the same pinned, verified aval release as the run action; fetches the trust policy from the default branch and pushes to its registry (credentials default to github.actor and github.token); downloads the artifacts into $RUNNER_TEMP; and runs aval push --test <name> per artifact with a fresh OIDC token, trying every artifact and exiting with the worst code (5 is never downgraded). stats: true also publishes each pushed test's run record, best effort. It is a composite action, not a reusable workflow, so the certificate names the calling workflow; CI checks this on Aval's main. No change to the aval binary, its exit codes or formats.
    • 15ade1b: New GitHub composite action integrations/github/run (#211): a CI job runs one test through Aval with uses: TrianaLab/aval/integrations/github/run@<sha> and with: {test: <name>} (inputs file and policy are optional). It refuses pull_request_target, workflow_run and any job with id-token: write; installs the aval release pinned in its action.yml, checked against the per-platform sha256, signature and provenance; fetches the trust policy, and the registry inside it, from the default branch through the contents API on every event (no policy: nothing is reused, with a warning); writes the outcome to the step summary; turns exit 5 into an aval SECURITY error annotation; uploads .aval/<test>/ as the artifact aval-<test> on a push to the default branch only; and warns when the policy trusts a refs/pull/ subject at or above minTrustLevel. The action pins 0.7.0 until the next release, which has --test and the policy's registry (#213). docs/guides/github-actions.md is rewritten around it. No change to the aval binary, its exit codes or formats.
    • ecc519f: aval init --set writes a two-file starting layout (#215): aval.yaml as a kind: TestSet with the test and one fragment holding the source globs, and .github/aval/policy.yaml with one placeholder keyless identity whose anchored subjectRegexp trusts no signer until <OWNER>/<REPO> is replaced. Scope and cacheability stay required. An existing file exits 2 unless --force. No format change.
    • 6a91ec3: The installers can pin and require verification for CI (#202). get-aval.sh --sha256 <hex> (or AVAL_SHA256; <os>_<arch>=<hex> per platform, the entry for the detected platform required) refuses an archive with another digest or one that checksums.txt does not list with it. --require-verify (AVAL_REQUIRE_VERIFY=1) makes a missing cosign an error, --require-provenance (AVAL_REQUIRE_PROVENANCE=1) does the same for gh; both need --version and exclude --no-verify. install.ps1 reads the same variables. Interactive installs behave as before. docs/install.md has a CI recipe, and Aval's own CI installs its pinned release this way.
    • 4f70316: aval run and aval verify take --min-trust-level (or AVAL_MIN_TRUST_LEVEL) to raise the trust policy's minTrustLevel for one run (#214), so one policy can trust developer keys on PRs and require runner on main. A value below the policy's minimum, or an unknown level, exits 2. A result below the raised minimum is a miss (exit 4), never exit 5. The verify report is unchanged. runner.command does not see AVAL_MIN_TRUST_LEVEL.
    • e5cf98f: The trust policy takes an optional registry field (#209). aval run and aval verify use it when neither --registry nor AVAL_REGISTRY is set, and the config: line names the source that won (registry=<x> (policy <file>)). Reading the policy from a protected branch now carries the registry too. A policy registry with credentials (user:password@) exits 2 without printing them.

    Format change (additive): kind: Policy gains an optional field under the same apiVersion. Older aval releases reject a policy that uses it (unknown field), which fails closed; policies without it work everywhere. - 83ba4b5: aval push --report-file FILE reads the report written by the aval run that recorded the result (#201). When its outcome is verified, push prints nothing to push: ..., signs nothing and exits 0, so split-credential publishing is one command and a stale result file is not published again. Any other outcome publishes the result as before. A report for another test id or fingerprint, an unknown report version or an unreadable report exits 1. No format changes: the predicate, verify report, fingerprint and exit codes are unchanged. - 1c8baae: aval push --test <name> publishes only the test an artifact is named after (#210). A result or report for another test, or for inputs other than the ones push recomputes from the checkout (a changed file or declared env value), exits 1 and publishes nothing. Behaviour changes: a report that records a security event (outcome verification-failed, or a rejected entry that failed verification) now makes push sign nothing and exit 5, where it used to publish; and aval push never publishes a non-deterministic test, it prints nothing to push: ... and exits 0. aval run --push is unchanged. - 8efc307: New optional contract field scope.root (#200): the path from the contract's directory up to the root of its tree, .. segments only (.., ../..). A contract such as aval/unit.yaml with root: .. behaves as if its file sat in the root: globs, outputs, allowMutable[].file and files, manifest and finding paths, and execution.outputs.files[].path are relative to the root; runner.command and environment.probe run there; the --result-file, --report-file and --stats-file skip set is computed against it. scope.contracts paths stay relative to the contract file. The root must lie inside the git working tree that holds the contract, otherwise aval run, explain, verify and push exit 2. aval explain prints the resolved root. Globs still cannot contain ...

    Format changes: additive change to the contract schema (aval.trianalab.io/v1 stays). Contracts without scope.root keep their fingerprint byte for byte; setting or changing it changes the contract manifest line and so the fingerprint. The manifest version (aval-fingerprint/v2) does not change. Older aval binaries reject a contract that uses the field. - a4e260c: -t/--test <name> on aval run, explain, verify and push selects one test of a contract file (#207). A TestSet of more than one test without --test exits 2 and lists the names; on a kind: Test the flag is optional and must equal metadata.name. With --test the output files default to .aval/<name>/{result,report,record}.json, and aval run removes a stale .aval/<name>/ first; without it nothing changes. aval explain --test <name> --expand prints the expanded standalone kind: Test, and aval explain --all [-o json] fingerprints every test without running anything, reports every failing test by name and exits 2 (or 1). A TestSet expands to at most 1024 tests in total, plain tests included.

    Format changes: additive CLI flags only. No new exit code; the verify report, predicate and manifest version do not change. - 013ebd5: The fingerprint skips every entry named exactly .git, whatever its type (#199). A linked worktree or a submodule has a .git file that holds a machine-specific path; a ** source glob used to hash it, so the main checkout, each worktree and each machine got a different fingerprint for the same commit and scope. They now share one, and the exclude: ["**/.git"] workaround is no longer needed. A .git symlink is skipped instead of failing the fingerprint. The match stays case-sensitive (.GIT is still an input). An exact glob such as source: ["pkg/.git"] now matches no file and fails the fingerprint (exit 1, matched no files). outputs skip a .git file too, so it is never published.

    Format changes: the fingerprint manifest moves from aval-fingerprint/v1 to aval-fingerprint/v2. Every existing attestation becomes a miss once, so each test runs again and publishes a v2 result; there is no fallback lookup by v1. - 26058a5: New contract kind kind: TestSet (#206): many tests in one file, with defaults, named fragments a test pulls in with use, and a matrix that creates one test per value. Merge order is defaults, the used fragments, then the test; lists are unioned, so nothing inherited is removed, and a toolchain, probe or scope.root key set to two values exits 2 naming both sources. matrix substitutes {var} into metadata.name and runner.command only. Each test expands to a standalone kind: Test and fingerprints byte for byte like it. Unknown or unused fragments, a fragment that uses another or sets exclude, runner, metadata, outputs, matrix or cacheability, an unknown {var}, duplicate expanded names and a scope.contracts entry that points at a TestSet exit 2. aval run, explain, verify and push take a TestSet of one test; selecting one test of many comes with #207.

    Format changes: additive new kind under aval.trianalab.io/v1. Older aval binaries reject kind: TestSet with exit 2 (fail closed). The manifest version (aval-fingerprint/v2) does not change.

    • 5871b37: Readable errors and reasons. Output escapes only control and non-printable characters (quotes and backslashes print as they are), and each cause of a joined error gets its own aval: line (an invalid contract) or is separated by ; in the report reason (an invalid policy). A reason is printed once, in the report: stderr no longer repeats it, and a verification failure adds a single aval: SECURITY: ... line that links to docs/trust-model.md. A signer missing from the policy gets the reason signer key id "<id>" is not in the trust policy (trust policy <file>) instead of the Sigstore error. Skipped lookups (no policy, no registry, --no-reuse, a cacheability class that is never or not allowed to be reused) say only why they did not look; they stay misses. No attest.Sign: or registry.Lookup prefixes reach users. Text-mode verify prints signer: (with the trust level name) and reference: lines for a verified result. non-deterministic is called "never reusable" everywhere.     • cb81760: scope.resolve detects registry overrides as the tools read them. pip variables match in any spelling pip reads (PIP_ then any letter case, - equal to _, one optional leading --: PIP_index-url, PIP___INDEX_URL). ~/.npmrc is read as ini, like npm: quotes stripped from keys and values, ; and # comments, keys under a [section] ignored, ${VAR} expanded in keys and values as npm does (an undefined variable stays literal); a line Aval cannot read (including one with U+2028 or U+2029, or a quoted key or value that is JSON other than a string) fails the fingerprint and sends no token. A floating Maven version fails when <latest> or <release> is a SNAPSHOT or not in <versions>. Errors show only the host of a URL, so a token in a registry path (https://npm-proxy.fury.io/<token>/user/) is masked too.

Pushing an attestation without a Sigstore bundle is now refused, since it could never verify. Keyless signing always uses the Sigstore public-good instance, as the CLI already did.
    • 9556f78: The mutable-reference scanner adds parser-based detection to its line-by-line pass, which still runs on every file it ran on before, so it finds everything it found before. Dockerfiles named as such (Dockerfile, Containerfile, Dockerfile.*, Dockerfile-dev, Dockerfile_windows, *.dockerfile) are also split the way BuildKit does: a comment line ending in \ no longer swallows the next instruction, continued lines join with nothing (FROM db:1\ then 6 is db:16), comment and blank lines inside a continuation are dropped, a leading # escape= sets the continuation character, and heredoc bodies are kept apart. YAML is also decoded: image: keys are matched by their decoded value ("ima\x67e":, ? image, !!binary, tagged, anchored or alias keys, nested sequences), after an anchor or an empty flow value, or after a lone CR, NEL or LS line break. The scanner also reports kustomize images: and imageTags: entries with newName, newTag or tagSuffix and no digest, kustomize patches, replacements, transformers, generators and helmCharts that set an image (by ref, such as patches[0]), kind: ImageTagTransformer, images in Helm *.tpl helpers, RUN --mount=...,from= images, JSON manifests under templates/ or listed in kustomize resources, Compose build.dockerfile_inline and docker-image:// additional_contexts, and every name of a multi-name or lowercase Dockerfile ARG. What Aval reports because it cannot tell (a templated key in a Helm template, a YAML key with an unknown tag or an undecodable escape, an undecodable heredoc name, a FROM image with a variable that is not a global ARG with a value, a kustomize resource that is remote or outside the scope (resources[2]), a tagged key in a template the parser rejects, a Dockerfile BuildKit refuses) is in the container ecosystem, so scope.allowMutable can acknowledge it; only an unreadable or oversized file stays in scan. A shell continuation at the very end of a file is no longer dropped. docs/pinning.md now says the scanner is a best-effort safety net and lists its known limits.

    • 6a2a118: aval stats finds run records on registries that do not sort tags, such as GHCR: it lists every tag and filters by the stats- prefix instead of starting the listing after stats. Up to 64 pages of tags are read (6400 tags at a registry page size of 100); past that the report carries a truncation warning.
    • 843f7a3: A symlink in the contract directory under which a source or dependencies glob could match files (for example pkg/sub -> /elsewhere with **/*.go), now fails the fingerprint with an error naming the path. Before, it was skipped, so edits behind it kept the same fingerprint and a stale result could be reused. A symlink no glob can reach is still ignored, and a contract directory that is itself a symlink fingerprints like its target.
    • 27d7391: Try Aval in the browser: click the terminal on the home page of the docs site (or its "Try it live" button) and it runs the real Aval compiled to WebAssembly, with a simulated test, an in-memory registry and a throwaway key generated in the browser.     0.2.0¶

    Minor Changes¶

    • 0148c76: Formats are frozen. The contract and policy apiVersion is now aval.trianalab.io/v1 and the verify report version is aval.trianalab.io/verify-report/v1; aval.dev/v1alpha1 contracts and policy files are rejected, so change that line in yours. The contract hash covers apiVersion, so results published before are misses and each test runs once. The predicate type (https://aval.trianalab.io/attestation/execution/v2), media and artifact types (application/vnd.trianalab.aval.execution.v2, application/vnd.trianalab.aval.fingerprint.v1) and predicate schemaVersion v2 are unchanged and now frozen, so attestations written by v0.1.0 keep a valid, readable format. Compatibility rules (additive changes within a version, what needs a new version, how consumers treat unknown fields and values, deprecation) are in docs/artifact-format.md, and golden files guard the JSON shape of the statement, predicate and verify report.

    Patch Changes¶

    • c17dc26: aval run and aval verify escape newlines and control characters in reasons printed as text and on stderr, so text from an untrusted attestation cannot start a log line of its own. Aval's own CI now reuses its signed e2e results, and a release requires a verified e2e attestation for its commit.
    • 59b9b66: pkg/evidence is semver-stable Go API: within a major version it changes additively only, and CI fails when an exported identifier is removed or changes type or signature without a new major module path. examples/evidence-consumer is a separate module that consumes Aval evidence through pkg/evidence alone, with its own signature verifier. The policy is in docs/integrations.md.
    • bbf9e55: Fingerprinting fails closed in two more cases: a scope.source glob that matches no file (a typo, or a name that differs on disk by case or Unicode form), and a file excluded only because a trailing ** in exclude matched zero segments (build/** against a file named build). Trees that fingerprinted before and still do keep the same fingerprint. A table-driven false-hit corpus now pins every kind of relevant and irrelevant change.
