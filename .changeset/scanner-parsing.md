The mutable-reference scanner adds parser-based detection to its line-by-line pass, which still runs on every file it ran on before, so it finds everything it found before. Dockerfiles named as such (`Dockerfile`, `Containerfile`, `Dockerfile.*`, `Dockerfile-dev`, `Dockerfile_windows`, `*.dockerfile`) are also split the way BuildKit does: a comment line ending in `\` no longer swallows the next instruction, continued lines join with nothing (`FROM db:1\` then `6` is `db:16`), comment and blank lines inside a continuation are dropped, a leading `# escape=` sets the continuation character, and heredoc bodies are kept apart. YAML is also decoded: `image:` keys are matched by their decoded value (`"ima\x67e":`, `? image`, `!!binary`, tagged, anchored or alias keys, nested sequences), after an anchor or an empty flow value, or after a lone CR, NEL or LS line break. The scanner also reports kustomize `images:` and `imageTags:` entries with `newName`, `newTag` or `tagSuffix` and no digest, kustomize patches, replacements, transformers, generators and `helmCharts` that set an image (by ref, such as `patches[0]`), `kind: ImageTagTransformer`, images in Helm `*.tpl` helpers, `RUN --mount=...,from=` images, JSON manifests under `templates/` or listed in kustomize `resources`, Compose `build.dockerfile_inline` and `docker-image://` `additional_contexts`, and every name of a multi-name or lowercase Dockerfile `ARG`. What Aval reports because it cannot tell (a templated key in a Helm template, a YAML key with an unknown tag or an undecodable escape, an undecodable heredoc name, a `FROM` image with a variable that is not a global `ARG` with a value, a kustomize resource that is remote or outside the scope (`resources[2]`), a tagged key in a template the parser rejects, a Dockerfile BuildKit refuses) is in the `container` ecosystem, so `scope.allowMutable` can acknowledge it; only an unreadable or oversized file stays in `scan`. A shell continuation at the very end of a file is no longer dropped. docs/pinning.md now says the scanner is a best-effort safety net and lists its known limits.
