"aval": patch

The mutable-reference scanner reads Dockerfiles the way BuildKit does: a comment line ending in `\` no longer swallows the next instruction, continued lines join with nothing (`FROM db:1\` then `6` is `db:16`), comment and blank lines inside a continuation are dropped, a leading `# escape=` sets the continuation character, and `COPY`/`ADD` heredoc bodies are not read as instructions. A Dockerfile BuildKit refuses (invalid or repeated directive, unterminated heredoc), or a heredoc name with a quote, backslash or `$` inside it, is a `scan` finding. YAML `image:` keys are matched by their decoded value (`"ima\x67e":`, `? image`, tagged, anchored or alias keys, nested sequences), also in a file that is not valid YAML (a Helm template), where a quoted key with an undecodable escape, an escaped `image` key whose value is not on its line, or a quoted key continued on the next line is a `scan` finding; YAML lines are no longer joined at a trailing `\`. `kustomization.yaml` `images:` entries with `newName` or `newTag` and no `digest`, or with a `tagSuffix`, are reported. A shell continuation at the very end of a file is no longer dropped.

A file that is valid YAML is now read by the YAML parser alone, so an `image:` value written after an anchor or an empty flow value, or after a lone CR, NEL or LS line break, is no longer missed. The scanner also reports kustomize `imageTags:`, kustomize patches and replacements that mention an image (`scan`), keys a Helm template writes (`scan`), images in Helm `*.tpl` helpers, Compose `build.dockerfile_inline` and `docker-image://` `additional_contexts`, every name of a multi-name or lowercase Dockerfile `ARG`, and a `FROM` whose `ARG` is given a value more than once (`scan`). An empty heredoc name (`<<""`) is a `scan` finding. docs/pinning.md now says the scanner is a best-effort safety net and lists its known limits.
