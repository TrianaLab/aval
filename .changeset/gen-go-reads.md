`aval gen go` adds to a package's fragment the files its code and tests read by a path it can resolve, such as `os.ReadFile(filepath.Join("../../fixtures", "order.json"))`: literals, constants, `filepath.Join`, variables, table tests, the package's own functions, methods and closures, the constants and helpers of other packages of the main modules and `runtime.Caller(0)`, through `os`, `ioutil`, `filepath`, `template.ParseFiles`/`ParseGlob` and `http.Dir`. A path a test passes to any function, such as `contract.Load("../../examples/shop.yaml")`, is added too. Paths under `t.TempDir()`, `os.MkdirTemp` and the like are not repository files, and a read in non-test code of a path its callers pass is checked at the caller. A test read it cannot resolve that may leave the package directory (from `os.Getwd`, the environment, a `..` literal joined with an unknown name, a function value or method it cannot follow, a `Chdir` to a computed directory) or a path outside the contract root fails with the file and line; `--go-allow-dynamic <pattern>` accepts them for the matching packages, whose authors declare those files by hand (docs: Guides, Generate scope from the dependency graph). An existing `aval gen go --check` in CI fails after the upgrade until each such package is fixed or listed with `--go-allow-dynamic`.
